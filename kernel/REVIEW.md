# Context review

Durable context should change when reality changes it.

It should not become an autonomous self-editing loop that mistakes every exception, trend, or wording preference for a constitutional crisis.

Review is the cold path.

Normal work reads the router and relevant context. Review begins only after a qualified signal or explicit human request.

## Qualify the interruption

A signal deserves review when it is material, persistent, or consequential and can plausibly change a real future decision.

Useful triggers include:

- repeated exceptions to a current model
- a successful deviation that outperforms the documented approach
- a capability or cost shift that removes an underlying constraint
- customer, buyer, or runtime behavior that contradicts durable truth
- a changed law, standard, market, platform, or dependency
- recurring model failure caused by missing or misleading context
- an explicit human challenge to the current judgment

Reject:

- isolated noise
- routine implementation failure
- curiosity with no decision consequence
- wording preference
- a trend report with no local implication
- an outcome already explained by current context
- a request to rewrite everything because one sentence is inelegant

Research supports review. Research is not the trigger by itself.

## Identify the level

Classify the challenged truth before editing:

**System issue**

Transferable judgment or the 2026 operating model is wrong, incomplete, or no longer useful across companies.

**Company issue**

The company's thesis, position, promise, boundary, capability, evidence, or cross-project model changed.

**Project issue**

The truth is local to one repository, product surface, market effort, implementation, or active project.

**Work issue**

The deviation is temporary and should remain in the current task or `.kernel/NOW.md`.

**No issue**

Current context remains valid. The signal does not earn a durable change.

Move learning no higher than the evidence supports.

## Gather decision-changing evidence

Start with internal reality:

- repeated outcomes
- successful and failed deviations
- user or buyer behavior
- runtime and production evidence
- conversion and retention
- delivery cost and reliability
- project history
- actual constraints and authority

Add repository analysis, connected sources, primary research, experiments, or external market evidence only when they can separate meaningful alternatives.

Look for counterevidence.

Stop when more evidence is unlikely to change the classification, proposed delta, or next test.

## Challenge the assumption, not only the sentence

Name:

- the current claim
- the assumption or cost model beneath it
- the trigger
- strongest evidence
- strongest counterevidence
- where the claim is still useful
- where it fails
- what decision becomes different

A sentence can be badly written while the judgment remains right.

A sentence can sound excellent while carrying an obsolete world model.

Review the thing that governs behavior.

## Propose the smallest complete delta

State:

- target level
- exact target file
- operation: add, remove, strengthen, weaken, split, merge, move, or rewrite
- replacement judgment or truth
- expected behavior change
- confidence
- remaining uncertainty
- next proof
- migration or contradiction created elsewhere

Do not rewrite a whole domain when one precise change installs the better model.

Do not preserve stale prose merely because other files link to it. Repair the route and delete the duplication.

## Authority

Agents may qualify, investigate, compare, challenge, and propose.

Project context may be changed when the active workflow grants project write authority.

Company context may be changed only when the active workflow grants authority to update company truth.

Shared system files change only after explicit human approval.

Do not let a project-specific exception silently mutate universal judgment.

## Validate the amendment

After a change, check:

- the new statement carries enough context to stand cold
- the decision boundary is clearer
- narrower files do not contradict it accidentally
- routes still load the right context
- no stale duplicate remains
- the hot path did not gain unnecessary weight
- examples and tests reflect the behavior
- a capable model can extend the new judgment beyond the triggering case

## Done

Review is done when the signal is classified, the evidence is sufficient, the smallest durable delta is clear, authority is respected, contradictions are repaired, and the next task will make a better decision without carrying the entire review history.
