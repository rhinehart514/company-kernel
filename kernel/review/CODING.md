# Question Engineering

Qualify a Coding review when one or more of these signals materially affect real work:

- the same standard creates repeated friction across meaningful changes
- several projects succeed by violating the same default
- a model, tool, runtime, framework, or infrastructure shift changes the economics
- a new security, reliability, scale, data, cost, or deployment constraint appears
- two Coding rules produce contradictory calls
- the architecture repeatedly bends around the same boundary or ownership model
- prescribed verification passes while meaningful reality still fails
- following the default compounds ceremony or complexity faster than value
- a human explicitly challenges a standard as stale, timid, or wrong

Ask:

- Is the shared judgment wrong?
- Is one project's technical model or implementation wrong?
- Is the failure actually Product, GTM, or company-level?
- Is there enough repeated or consequential evidence to change anything?

One ugly Tuesday in one repository is not a new constitution.
