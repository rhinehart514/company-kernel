# Repository rules

This repository steers already-capable models. Prefer removing instructions to explaining common sense.

Keep the portable core host-agnostic. Put client-specific metadata in adapters, not in shared skill judgment.

Beliefs belong in references. Verbs belong in skills. Current project truth belongs in the target project's context files.

Do not replace a user's existing instruction system. Integrate minimally and preserve stronger local rules.

Split target context by cadence, authority, or real size, not by an assumed company org chart. Never create empty domain files for completeness.

Every instruction must earn its context cost through a trigger case, behavior case, observed failure, or clear safety boundary.

Run `python3 scripts/validate.py` before committing.
