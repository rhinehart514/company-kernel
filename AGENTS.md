# Repository rules

Company Kernel should make a frontier model better before it sees the task.

The model starts capable. It does not start with our view of the world, our company, this project, or the decisions already earned by reality. Build the smallest context system that transfers those things without slowing normal work.

## The architecture

- `kernel/` is the canonical system layer.
- `templates/` defines the smallest company and project context that can be installed safely.
- `skills/` contains repeated operating behavior, not another doctrine library.
- `scripts/` contains deterministic installation, initialization, inspection, and validation.
- `examples/` proves system to company to project inheritance in a real shape.

System files install worldview and reusable judgment.

Company files contain truth that should survive across projects.

Project files contain truth specific to one repository or outcome.

Work instructions contain the immediate task.

More specific context narrows broader context. It does not silently rewrite it.

## Write for the model we actually have

Assume intelligence. Never assume context.

Do not hand the model the final twenty percent of a conclusion and expect it to reconstruct the experience that produced it. Give important calls enough roots that the model can extend them into situations we did not enumerate.

Every section should contain at least one thought worth carrying into the work. Prefer language that sharpens judgment, expands ambition, or makes a decision boundary visible.

Do not write corporate documentation, generic startup advice, slogan piles, fake certainty, or framework theater.

Lead with the call. Use exact nouns. Make the consequence visible. Stop when the idea is installed.

## Keep the hot path lean

Normal work must not load the whole company constitution.

The router loads only the system domains and company or project files that can materially change the decision. Mechanical work should remain mechanical. Cross-domain work should not hide behind a narrow task label.

Do not add a domain, skill, agent, index, database, or generated summary because the diagram has room for one.

## Authority

Preserve stronger user, repository, safety, permission, security, deployment, and approval rules.

Agents may update project truth when authorized. Company truth requires the authority granted by the active workflow. Shared system judgment changes only through explicit human approval.

Observed reality outranks stale context.

Run `python3 scripts/validate.py` before committing.
