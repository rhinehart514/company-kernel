# First run

The first run should feel like the environment understands the company, not like another template arrived.

## Run

```text
$system-integrate Build or reconcile the shared Company Kernel system above my projects.
Inspect my existing global rules, installed skills, and available tools.
Keep stronger rules. Write a readable 1-10 line SYSTEM.md and only useful lenses
under ~/.company-kernel, create a clear capability map, then initialize this repository
with PROJECT.md and .project/NOW.md. Do not delete or rewrite unrelated global work.
```

## What it should inspect

- global and project instruction files
- installed global and project skills
- runtime tools and connected sources
- tool configuration paths without exposing secrets
- repository behavior, recent changes, product surfaces, tests, and docs
- existing system and project context
- first-party evidence available to the host
- current external reality when it can change the project

## What it should leave

```text
~/.company-kernel/SYSTEM.md
~/.company-kernel/LENSES.md
~/.company-kernel/lenses/*
~/.company-kernel/CAPABILITIES.md

PROJECT.md
.project/NOW.md
```

It may add project files, project-local skills, scripts, or routes when they solve a real repeated problem.

## What the report should lead with

1. **Project truth**
2. **The calls**
3. **Product coherence**
4. **Frontier unlock**
5. **Trajectory**
6. **Shared system**
7. **Capability changes**
8. **Next proof**

File operations and withheld global changes come last.

A report that leads with “created four markdown files” has confused the residue with the result.
