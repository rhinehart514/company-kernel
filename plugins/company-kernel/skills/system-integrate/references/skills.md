# Skill judgment

A skill should save a capable model from reconstructing the same non-obvious job every time.

Create or keep one only when it has:

- a repeated job
- clear positive and negative triggers
- a meaningful result or state change
- distinctive judgment, workflow, environment knowledge, scripts, or assets
- evidence that the model, context, current skills, and tools are not enough

The description is routing policy. Put the job and trigger first.

Keep `SKILL.md` focused on inputs, authority, decisions, tool use, output, stopping, and verification.

Use project-local skills to prove project-specific capability. Promote them only after they work across unrelated projects.

Do not merge skills because their names share a department. Do not create a skill to restate the shared system.

Before retaining a new skill, test prompts that should trigger, prompts that should not, representative behavior, and a case where stronger local rules must win.
