# Review Protocol

A signal is not a review. Qualify it before loading expensive context.
Review only when the signal is material, persistent or consequential, plausibly changes a real decision, and belongs to this domain.
Inspect the current system standard, matching project model, internal outcomes, counterevidence, and external change only as needed.
Classify every finding as a system issue, project issue, cross-domain issue, or no issue.
Challenge the underlying assumption, not merely the wording of a file.
Propose the smallest justified delta: add, remove, strengthen, weaken, split, merge, or rewrite.
Agents may research, compare, challenge, and propose. Shared system standards change only after explicit human approval.
Record rejected or deferred judgments only when forgetting them would cause repeated waste.
