# Project research

Resolve one question that can change a real decision.

## Start with the decision

Read the shared Company Kernel system and the project context relevant to the question.

State what decision, belief, boundary, or bet the research can change. Narrow the question until evidence can separate meaningful alternatives.

Read [research judgment](references/research.md).

## Investigate

Use the repository, first-party project evidence, web, browser, connected sources, code, datasets, and tools that match the evidence needed.

Prefer current primary evidence for changing technical, legal, regulatory, market, company, and product facts.

Look for contradiction on purpose. Do not use an arbitrary source count. Do not fan out to several agents unless the work divides into independent valuable streams.

## Interpret

Separate observation, inference, unknown, and counterevidence.

Translate external change into project consequence. A model release matters only when it changes reliability, cost, interface, authority, economics, or product boundary.

## Stop

Stop when more research is unlikely to change the decision or next test.

When direct reality can answer faster, build, sell, observe, or run the smallest credible experiment.

## Update

When authorized and the evidence changes project truth, rewrite the relevant project file. Keep dates, provenance, contradiction, and uncertainty where they matter.

Do not edit the shared system. If a shared belief appears stale, report it and recommend `$system-integrate`.

Return the conclusion, strongest evidence and counterevidence, project change, remaining uncertainty, and next proof.
