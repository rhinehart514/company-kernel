# Project Research

Resolve one project-shaping uncertainty.

The output is not a literature pile. It is a better decision, a changed belief, a bounded next test, or justified confidence that the project model should remain unchanged.

## Begin with the project

Read `PROJECT.md` and the linked context relevant to the question.

If no project context exists, inspect the repository and current instructions before substituting assumptions.

State the decision, belief, boundary, or bet that the research could change.

Narrow the question enough that evidence can separate meaningful alternatives.

## Research current reality

Read [references/research.md](references/research.md).

Use the host's available repository tools, web search, browser, connected sources, code execution, datasets, or other capabilities according to the evidence needed.

Prefer first-party project evidence before generic market assumptions.

Use current authoritative sources for changing technical, legal, regulatory, company, product, and market facts.

Search for contradiction deliberately.

Do not use an arbitrary source count.

Do not fan out to several agents unless the work divides into independent, valuable streams. Shared-context questions usually benefit from one strong investigator.

## Interpret

Separate:

- what was observed
- what was inferred
- what remains unknown
- what changed relative to the prior project model
- what would falsify the conclusion

Translate technical or market change into project consequence.

A model release matters only if it changes reliability, cost, interface, authority, product boundary, economics, or another real constraint.

A competitor launch matters only if it changes evidence about demand, category behavior, distribution, capability, or timing.

## Stop

Stop when more research is unlikely to change the decision or next experiment.

When direct reality can resolve the question faster, recommend or run the smallest credible test rather than extending desk research.

## Update

If the task authorizes edits and the evidence materially changes project truth:

- update the relevant existing context file
- rewrite stale claims
- preserve contradiction and uncertainty
- include dates or provenance where freshness matters
- do not create a new file merely to store the research

If the evidence does not change the project model, say so.

## Return

1. the decision-impacting conclusion
2. strongest evidence and counterevidence
3. what changed or did not change in project context
4. remaining uncertainty
5. the next action or proof with the highest decision value
