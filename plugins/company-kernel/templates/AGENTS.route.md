## Company context

`COMPANY.md` is the canonical shared model of the company. It applies across human operators and agents.

Read it for work that can materially change company direction, market, buyer, owned result, responsibility, product or delivery form, pricing, economics, distribution, major onboarding, expansion, or company-level narrative.

Do not load or edit it for isolated bugs, routine refactors, dependency updates, tests, or implementation work incapable of changing a company contract.

Use:

- `$company-model` to initialize or reconcile `COMPANY.md`
- `$opportunity-evaluate` before committing to a material new product, market, service, channel, pricing model, or adjacent workflow
- `$market-probe` to resolve one external uncertainty that could change `COMPANY.md` or an opportunity verdict

When no stronger project rule exists, context precedence is:

1. explicit current direction from an authorized human
2. current delegated direction
3. `COMPANY.md`
4. relevant domain documents
5. relevant operator context
6. implementation inference

Operator context does not override shared company context unless the operator has explicit decision authority. Implementation authorship does not imply strategic authority.

Code proves capability, not demand. Customer behavior supports demand. Sales behavior supports buying. Economic data supports viability. Agent synthesis remains inference.
