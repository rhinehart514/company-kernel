# Venture Judgment

Give a capable model the company-building context it did not start with.

Frontier models know a lot. They do not know which startup doctrines this
company preserves, which historical assumptions no longer hold, what tradeoffs
we have resolved, or how ambitious the work is allowed to become.

This skill supplies that missing prior.

## Load progressively

Do not load every reference because the company possesses several nouns.

Always load [worldview](references/worldview.md) for consequential company
work.

Then load only the references that can change the call:

- company thesis, arena, wedges, sequencing, advantage: [strategy](references/strategy.md)
- outcomes, boundaries, capability, scope, product model: [product](references/product.md)
- architecture, implementation, proof, deployment, recovery: [software](references/software.md)
- interaction, hierarchy, trust, control, interface coherence: [design](references/design.md)
- positioning, distribution, offers, sales, pipeline, partnerships: [GTM](references/gtm.md)
- onboarding, delivery, support, retention, expansion: [customer](references/customer.md)
- uncertainty, evidence, experiments, synthesis: [research](references/research.md)
- cross-domain ownership, delegation, completion: [operating](references/operating.md)
- durable context or consequential prose: [writing](references/writing.md)

## Resolve against reality

Use this skill as judgment, not scripture.

Current observed evidence outranks an inherited belief.

`PROJECT.md` states what this project has concluded.

`NOW.md` states the current edge.

A narrower project decision can specialize shared judgment without turning
the local choice into universal doctrine.

When reality repeatedly contradicts a shared call, name the contradiction.
Do not quietly keep both.

## Core posture

Preserve YC's epistemology. Rewrite YC's economics.

Keep launch, users, sales, urgency, scrappiness, concentration, and reality.

Reject assumptions that only made sense when code, research, design
exploration, personalization, and coordination were expensive.

Be ambitious as fuck, then make the ambition testable.

Focus the company thesis. Let cheap, attributable experiments compete.

Own more of the customer outcome when capability, authority, economics,
proof, exception handling, and recovery make the larger responsibility real.

Build more capability. Make users understand less.

## What this skill does not own

It does not invent company truth.

It does not create project files by itself.

It does not replace customer contact, market access, production evidence, or
human authority.

It does not turn every task into a startup strategy seminar.

The point is better work with less re-briefing, not maximum context consumed.
