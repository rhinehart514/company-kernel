# Kernel Review

Question durable context only when reality earns the interruption.

## Modes

- **qualify:** decide whether a signal deserves review
- **review:** inspect evidence and propose the smallest durable delta
- **audit:** compare system, company, and project context without changing it
- **apply:** make an already approved change at the authorized level

## Load the review path

Locate the system through the active route, `COMPANY_KERNEL_HOME`, or `~/.company-kernel`.

Read:

- `KERNEL.md`
- `REVIEW.md`
- only the system domains implicated by the signal
- `COMPANY.md` and matching company domain files
- `PROJECT.md`, `.kernel/NOW.md`, and matching project domain files
- the evidence that triggered review

Do not load every domain because the company possesses several nouns.

## Qualify before researching

A review requires a material, persistent, or consequential signal that can plausibly change a real future decision.

Useful signals include repeated exceptions, successful deviations, changed capability economics, recurring model failure, buyer or customer behavior, production evidence, a changed external constraint, or explicit human challenge.

Reject routine implementation failure, isolated noise, wording preference, curiosity, trend reports with no local consequence, and outcomes already explained by current context.

Research supports review. Research is not the trigger itself.

## Classify the level

Every finding must be one of:

- **system issue:** transferable judgment should change across companies
- **company issue:** cross-project company truth should change
- **project issue:** local project truth should change
- **now issue:** temporary state should change
- **no issue:** current context remains valid

Move the change no higher than the evidence supports.

A project deviation can be successful without disproving the system. A changed system prior can matter without changing this company today.

## Gather only decision-changing evidence

Start with internal outcomes:

- repeated exceptions
- successful and failed deviations
- user, buyer, or customer behavior
- runtime and production evidence
- conversion, retention, and delivery outcomes
- cost or reliability changes
- project and company history

Add repository analysis, connected sources, primary research, experiments, or direct market contact only when they can separate meaningful alternatives.

Look for counterevidence. Stop when more evidence is unlikely to change the classification, delta, or next test.

## Challenge the assumption

Name:

- the current claim
- the assumption or cost model beneath it
- the trigger
- strongest evidence
- strongest counterevidence
- where the claim still works
- where it fails
- what future decision becomes different

Do not confuse bad wording with bad judgment. Do not let excellent wording protect an obsolete belief.

## Propose the smallest complete delta

Specify:

- target level
- exact target file
- operation: add, remove, strengthen, weaken, split, merge, move, or rewrite
- replacement judgment or truth
- expected behavior change
- confidence and remaining uncertainty
- next proof
- migration or contradiction created elsewhere

Do not rewrite a whole domain when one precise change installs the better model.

A strong amendment gives the cold model enough context to extend the new call. It does not preserve the whole review transcript.

## Authority

Agents may qualify, investigate, compare, challenge, and propose.

Project context changes require project write authority.

Company context changes require authority to update company truth.

Shared system files change only after explicit human approval.

Applying an approved system change includes repairing routes, examples, templates, skills, validation, and stale duplication affected by it.

## Finish

Report:

1. trigger and qualification
2. challenged claim and underlying assumption
3. evidence and counterevidence
4. level classification
5. exact proposed delta
6. expected behavior change
7. authority required
8. contradictions or migrations created
9. next proof

If no durable change is earned, say so and return to the work.
