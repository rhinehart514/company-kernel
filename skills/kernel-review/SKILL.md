# Kernel Review

Question the current judgment only when reality earns the interruption.

## Modes

- **qualify:** decide whether a signal deserves review
- **review:** inspect evidence and propose a delta
- **audit:** compare standards and project models without changing either

## Select the domain

Choose Coding, Product, GTM, or an explicit cross-domain review.

Read `kernel/review/REVIEW.md` and only the matching domain trigger file. Then read the current system standard, project model, and relevant evidence.

Do not load every domain because the company possesses several nouns.

## Qualify before researching

A review requires a material, persistent or consequential signal that can plausibly change a real decision and belongs to the selected domain.

Reject routine implementation failure, isolated noise, wording preference, curiosity, trend reports, and external news with no project consequence.

Research supports review. Research is not the trigger itself.

## Gather only decision-changing evidence

Use internal outcomes first:

- repeated exceptions
- successful deviations
- failures
- user or buyer behavior
- runtime evidence
- conversion
- cost or reliability changes
- project history

Add repository analysis, connected sources, web research, primary technical sources, experiments, or direct market contact only when they can separate meaningful alternatives.

Look for counterevidence. Stop when more evidence is unlikely to change the classification or next test.

## Classify

Every finding must be one of:

- **system issue:** transferable judgment should change
- **project issue:** current project truth, direction, or implementation should change
- **cross-domain issue:** ownership or company-level judgment is unresolved
- **no issue:** current standards and models remain valid

## Propose the smallest delta

Name:

- challenged assumption
- trigger and qualification
- strongest evidence and counterevidence
- exact target file
- operation: add, remove, strengthen, weaken, split, merge, or rewrite
- expected consequence
- confidence and remaining uncertainty
- next proof

Do not rewrite whole files when one precise delta is enough.

## Authority

Agents may qualify, research, compare, challenge, and propose.

Shared system standards change only after explicit human approval. Apply project-model changes only when the user authorized edits or the active workflow clearly grants that authority.
